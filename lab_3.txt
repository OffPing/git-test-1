Ваша задача научиться работать с ветками в соответствии с инструкцией.
Начальная настройка репозитория
При запуске нового проекта мы также инициализируем новый репозиторий.

1. Запустить git init -b develop
2. Убедитесь, что ваше имя автора и адрес электронной почты указаны правильно:

git config user.name "my name"
git config user.email "my@email.com"

3. Отключить быструю перемотку слияния:
git config branch.main.mergeoptions "--no-ff"
git config branch.develop.mergeoptions "--no-ff"

4. Следующие файлы должны быть добавлены в каждый новый репозиторий:
a. README.md - содержит следующую информацию:
i. Краткое описание назначения кода, который лежит в этом репозитории;
ii. Настройка разработки;
iii. Ссылка на этот дополнительный руководящий документ (упоминания этого достаточно).

b. CHANGELOG.md - сначала пусто, но при каждом выпуске необходимо указывать новую версию и изменения.

5. Первое commit message должно быть «initial commit» и содержать вышеупомянутые файлы. С этого момента необходимо соблюдать гайдлайн по коммитам из предыдущей ЛПР.
Инструкция по работе с ветками
В вашем проекте должны быть обязательно три типа веток:
 ветка main: содержит потенциально готовое к выпуску и протестированное программное обеспечение. На main не делается никаких коммитов, кроме слияния из develop. Каждая слияние коммит получает тег Git с соответствующей версией.
 ветка develop: это ветка интеграции. Как только было решено, что релиз готов, он объединяется с основным с помощью коммита слияния. При develop не производится никаких коммитов, кроме слияния веток feature и обновления CHANGELOG.md.
 Ветки feature: они называются feature/<descriptive-feature-name> и создаются из ветки develop. Как только функция завершена и стабильна, она объединяется в develop с помощью коммита слияния. Название функциональной ветви должно быть описательным.
Слова разделяются знаком -. Полное имя ветки не должно быть длиннее 80 символов.
Кроме обязательных вы можете использовать следующие типов веток:
build: Сборка проекта или изменения внешних зависимостей
ci: Настройка CI и работа со скриптами
docs: Обновление документации
fix: Исправление ошибок
perf: Изменения направленные на улучшение производительности
refactor: Правки кода без исправления ошибок или добавления новых функций
revert: Откат на предыдущие коммиты
style: Правки по кодстайлу (табы, отступы, точки, запятые и т.д.)
test: Добавление тестов

Задание заключается в выполнения предыдущей ЛПР (начиная с Задание 3), но уже с использованием веток. Вы должны точно соблюдать инструкцию предложенную выше.
